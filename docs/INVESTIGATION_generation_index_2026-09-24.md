# What generation order can each tool honestly report?

Step 1 of Stage 1 in [NEXT_STAGES.md](NEXT_STAGES.md), and a precondition for
item AD. Source-level investigation of all eight design tools, 2026-09-24.

---

## The premise that was wrong

`PLAN_binderscout_v2.md` treats AD's Evaluator half as "one line each": every
extractor globs its tool's per-design outputs, so `stat()` yields a generation
time. **Seven of eight extractors instead resolve one aggregate CSV and iterate
its rows** (`bindcraft.py:64,90`, `boltzgen.py:59,71`, `mosaic.py:68,108`,
`proteina_complexa.py:173,201`, …), where a file mtime is one timestamp for the
entire pool.

The investigation found the reality is worse than "mtime doesn't work", and
better than "nothing works" — but only per tool, and never by row position.

---

## Verdicts

| tool | file the extractor reads | row order | honest index available? |
|---|---|---|---|
| **BindCraft 2** | `3_Ranked/!_Ranked.csv` | sorted (`i_pDAE` desc) | **yes** — join to `1_Trajectories/!_Trajectories.csv` on `hash`, take `trajectory` |
| **Protein-Hunter** | `summary_high_iptm.csv` | generation | **yes** — the `run_id` column *is* the index |
| **Mosaic** | `designs.csv` | sorted (two sorts) | **yes** — `generation_index`, captured pre-sort |
| **BoltzGen** | `final_designs_metrics_*.csv` | sorted (`final_rank`) | **yes** — parse the zero-padded integer out of `id` |
| **RFD3** | `sequences.csv` (*we* write it) | lexicographic | **yes** — parse `_(\d+)_model_(\d+)$` |
| **BindCraft 1** | `final_design_stats.csv` | **conditional** | **partial** — no counter exists anywhere |
| **PXDesign** | `sequences.csv` | lexicographic | **no** — `_sample_<i>` is a batch index, not a time index |
| **Proteina-Complexa** | `top_samples_*.csv` | sorted (`total_reward`) | **no, structurally** |

Three findings that change the design:

**Row position is never usable.** Not for a single tool. Even where the file is
in generation order (Protein-Hunter), the extractor re-sorts before iterating
(`protein_hunter.py:146-153`). The index must come from a column or a parsed
identifier, never `df.iterrows()` position.

**BindCraft 1 is genuinely partial, and its failure is silent.**
`final_design_stats.csv` is rebuilt sorted by `Average_i_pTM` when a campaign
fills its quota (`generic_utils.py:148-171`), but left in append order when it
stops early. The two cases are distinguishable only by the `Rank` column being
`1..N` versus blank. No attempt counter is written to any CSV — the in-memory
`trajectory_n` never reaches disk. The best available signal is
`mpnn_design_stats.csv` row order, which is not what the extractor reads.

**Proteina-Complexa is not missing a counter; a linear index is the wrong
shape.** Under MCTS the pool is a flattened tree mixing lookahead roll-outs with
terminal states, and `keep_lookahead_samples` is the shipped default. A
lookahead from the last checkpoint is later than one from the first, every final
is later than all lookaheads, and the search deliberately revisits ancestors, so
designs share trajectory prefixes. The honest analogue is `(checkpoint, sim_idx)`
parsed from `metadata_tag`, and it exists for lookaheads only. `sequences.csv`
is worse still: `evaluate.py:799` does `random.shuffle(sample_paths)`.

This is what `generated_at_source` must be able to say. `unavailable` is a
first-class answer, and for two tools it is the *correct* one.

## The second problem, which is arguably larger

Ordering is only half of it. **Most extractor inputs are already downstream of a
quality filter**, so a discovery rank computed on them is conditioned on
survival:

| tool | pool the extractor sees |
|---|---|
| Protein-Hunter | `iptm > 0.8` **and** `plddt > 0.8` **and** Ala ≤ 20% (the cap is a hardcoded `0.20`, not `--percent_X`) |
| Mosaic | `is_top=1` — the top ~5% by quality rank |
| BoltzGen | budget + diversity selection, typically ~700 rows of ~10,000 generated |
| Proteina-Complexa | `top_samples`, then only survivors reach `evaluation_results/` |
| BindCraft 1 | accepted designs only, intersected with PDBs still on disk |

"How early did a good design appear", measured over a pool pre-filtered for
being good, is a biased estimator: the denominator — everything generated by
time *t* — has been deleted. For Mosaic and Protein-Hunter a complete pool is
reachable (`--all-mosaic-designs`, `--all-protein-hunter-designs`); for BoltzGen
`aggregate_metrics_*.csv` is near-complete but unread; for Proteina-Complexa the
complete-ish `all_rewards_*.csv` is never read either.

**Recommendation:** AD should not ship a discovery-rank number for a pre-filtered
pool without carrying that fact in the output. The extractors already model this
— `pool_pre_filtered` exists in `tool_classification.py` — so the metric should
refuse, or flag, rather than quietly report a conditioned statistic.

## Incidental findings, verified

Not part of AD; found while reading, and each independently checkable.

- **BoltzGen is mislabelled as an unfiltered pool.**
  `tool_classification.py:92` sets `pool_pre_filtered_default=False` while
  `source_csv_default` is `final_designs_metrics_*.csv` — a budget-sized
  quality-and-diversity selection. Same at `:106` and `:120` for the nano and
  protein variants.
- **The PXDesign collector's preferred path is dead code.**
  `configurator.py:1603` globs `filtered_summary.csv`, but PXDesign's own
  `cleanup_outputs` unlinks that file (`helpers.py:901-906`) before the
  collector runs. Strategy 1 can never match, so every run takes Strategy 2 —
  which has no `rank`, so `pxdesign_rank` / `pxdesign_bucket` ship empty.
- **RFD3's run script sorts lexicographically.** `configurator.py:2761` and the
  shipped template both do `sorted(mpnn_dir.glob("*.fa"))`, which orders
  `_10_model_0` before `_2_model_0`. Harmless today — order does not affect
  extraction — but it diverges from generation order for any run with ≥10
  batches, and the templates use 88.
- **CLAUDE.md misattributes Protein-Hunter's drop-out.** The "no eligible best
  design" note credits `--percent_X`; that flag controls X-masking during
  sequence sampling. The gate is a literal `0.20` alanine cap at
  `pipeline.py:586-589`, alongside the two threshold tests.

## Provenance and limits

All claims are from source. **No completed BindCraft 1 or BindCraft 2 campaign
exists in this tree** to check against — `runs/MINBC/` and `runs/MIN_BINDCRAFT2/`
are config-only, and the archived CBG/CALCA pools are outside it. The BindCraft
verdicts in particular are therefore unverified against real output, and the
`Rank`-blank heuristic for detecting an early-stopped campaign should be
confirmed on a real file before anything depends on it.
